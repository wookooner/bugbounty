# 버그바운티 연구 원칙

사용자가 제공한 2026-11-24 실무 원칙을 이후 세션에서 적용할 수 있도록 요약했다.

1. **범위부터 고정한다.** 공식 정책에서 자산 유형별 포함·제외, 허용 환경·계정, 금지 행위, 데이터 취급, 영향·심각도 기준, 공개·제보 채널을 확인한다. 소스는 커밋, 배포는 체인·주소·기준 블록과 연결한다. 애매한 자산은 확인 대기로 기록한다.
2. **인접 시스템과 신뢰 경계를 연결한다.** 범위에 해당하면 웹·API·지갑 서명·RPC·인덱서·컨트랙트·키·멀티시그·거버넌스를 같은 자산 목록에서 추적한다. 인증·인가, 서명 도메인·논스·만료, 오프체인과 온체인 상태의 일치, 관리자 권한과 자금 흐름을 대상에 맞게 확인한다.
3. **검증 가능한 단위로 기록한다.** 검토 항목마다 지켜야 할 규칙, 전제조건, 기대값과 관찰값, 고정 소스 위치, 실행 환경과 결과를 남긴다. 관찰·가설·확인된 결함을 구분하고 미실행이나 실패의 이유도 보관한다. 방어적 동작은 승인된 격리 환경과 자체 테스트 계정으로 확인한다.
4. **중복과 영향을 대조한다.** 프로그램 Known Issues, 공개 권고와 관련 감사를 확인한 범위만 적는다. 실제 영향과 현실적인 전제조건을 근거로 프로그램의 기준에 맞춰 심각도를 판단한다. 근거가 충분해질 때까지 판단과 제출을 보류한다.
5. **보고서는 근거 중심으로 짧게 유지한다.** 확인된 결함 기록에는 제목·유형, 영향 자산과 버전, 원인과 전제조건, 확인 증거와 실제 영향, 완화 방안, 심각도 근거, 미확인 사항을 담는다. 원본 로그와 집계용 데이터는 대상 폴더의 증거와 연구 기록에 둔다.
6. **사람이 최종 판단하고 제출한다.** AI는 정책 요약, 코드·문서 분석, 방어적 테스트와 기록 정리를 지원한다. 공개·제출은 사용자가 결정한다. 일반 취약점 제보와 SEAL Safe Harbor의 별도 구조 절차는 각 적용 기준을 확인한다.
